# ReviewDNA v0.2.0 — Engineering Knowledge Mining

ReviewDNA v0.2.0 is the first release that presents the project as a complete pre-v1 engineering-knowledge mining platform rather than only a foundation CLI.

It keeps the original promise intact: **every discovered convention stays tied to review evidence, generated knowledge is not repository policy, and humans remain the final authority.**

## Highlights

### Stronger evidence model

- Evidence dispositions for accepted, adopted, acknowledged, unresolved, and conservative rejected-candidate signals.
- Explicit PR-author response inference.
- Optional deep commit→head same-file evidence.
- CODEOWNERS-aware evidence weighting without guessing team membership or ranking people.
- Explainable confidence contributions and rejection penalties.

### Semantic intelligence without surrendering control

- Provider-neutral embedding abstraction.
- Deterministic local feature embeddings.
- Ollama and OpenAI-compatible embedding providers.
- Guarded semantic clustering with category/polarity boundaries and complete-link protection.
- Optional grounded wording refinement that cannot create evidence, alter confidence, or bypass human decisions.

### Documentation drift and rule evolution

- AGENTS/CLAUDE/CONTRIBUTING/Copilot/Cursor documentation scanning.
- Lexical and optional semantic support/conflict matching with auditable provenance.
- Parent/child rule relationships.
- Conservative supersession detection.
- Evidence-derived rule timelines and Watch deltas.

### Human governance and reviewable publication

- Stable-ish rule fingerprints for tracked decisions.
- `review`, `ignore`, `promote`, and `override` decisions in `reviewdna.decisions.json`.
- Evidence-backed Knowledge Proposal bundles.
- Dry-run-first `publish-proposal` flow with explicit `--apply` required for GitHub writes.
- Publisher restricted to `reviewdna/*` branches and `.reviewdna/proposals/<id>/`; existing policy files are never silently overwritten.

### Incremental and privacy-aware analysis

- Incremental GitHub PR cache using `updated_at`.
- Stable content/options hashes and versioned resumable checkpoints.
- `--resume`, checkpoint validation, and cache compatibility tests.
- Token/cost preflight for optional remote stages.
- User-supplied pricing and aggregate remote-cost budget guard.
- Targeted secret/PII redaction that automatically disables raw caches/checkpoints when privacy controls are active.

### Rich dashboard and developer ecosystem

- Review Hotspots and Automation Opportunities.
- Documentation provenance, rule relationships, and evolution timelines in the static dashboard.
- Exportable 1200×630 SVG share card.
- Public Draft 2020-12 `AnalysisResult` JSON Schema.
- Executable programmatic API example.
- Versioned `@reviewdna/plugin-sdk` contracts for collectors/providers/exporters/scorers.
- GitLab collector prototype with self-hosted base-URL support and offline tests.

### Production-oriented hardening

- Node.js 20/22/24 CI.
- Windows/macOS/Linux CLI E2E.
- Docker smoke builds.
- Immutable released-Action smoke testing.
- CodeQL.
- Deterministic fuzz/security regression coverage.
- Schema ABI and fingerprint compatibility tests.
- Reproducible synthetic 10k-review benchmark with broad catastrophic-regression guards.
- Generated static documentation site and pre-v1 migration guide.

### GitHub showcase

- New visual README optimized for the first 10–15 seconds of a repository visit.
- Real CI/CodeQL/Release/License/Node/TypeScript badges.
- 60-second synthetic demo path.
- Mermaid workflow and system architecture diagrams.
- Repository-owned social/showcase SVG.
- Launch checklist, recommended Topics, social copy, and Featured Project copy for a personal site.

## Try it

```bash
git clone https://github.com/ahmed2qaid/reviewdna.git
cd reviewdna
npm install
npm run build
node apps/cli/dist/index.js analyze-fixture fixtures/reviews.json --out demo-output
```

Then open:

```text
demo-output/reviewdna-report.html
```

Analyze a GitHub repository:

```bash
GITHUB_TOKEN=github_pat_xxx \
node apps/cli/dist/index.js analyze owner/repository \
  --max-prs 100 \
  --min-evidence 2
```

## GitHub Action

After this release is published, workflows can pin the immutable release tag:

```yaml
- uses: ahmed2qaid/reviewdna/action@v0.2.0
  with:
    repository: owner/repository
    max-prs: '100'
    min-evidence: '2'
```

For stronger supply-chain pinning, use the exact commit SHA behind `v0.2.0`.

## Compatibility

- Node.js: `>=20`
- `AnalysisResult.schemaVersion`: remains `1.0`
- Plugin API: remains `apiVersion: '1'`
- Fingerprints remain pre-v1 identity anchors and are regression-tested, but a permanent v1 compatibility guarantee has not been declared yet.
- npm publication is intentionally not claimed until packages are actually published.

## Remaining pre-v1 work

ReviewDNA still treats real-world calibration as a hard requirement before claiming v1 stability. Synthetic and fixture benchmarks protect regressions, but they do not substitute for labeled real-world review histories.

GitHub Pages and public GHCR visibility may also require one-time repository/package administrative settings even when their build/publish workflows are already prepared.
